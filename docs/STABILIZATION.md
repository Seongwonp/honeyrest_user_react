# HoneyRest React 안정화 기록

점검일: 2026-08-09

## 작업 원칙

- 검색, 상세, 객실, 인증 순으로 핵심 사용자 흐름을 검증한다.
- 외부 이미지나 지도 서비스 실패가 페이지 전체 오류 또는 포커스 이동을 일으키지 않게 한다.
- 각 단계는 프로덕션 빌드와 실제 브라우저 렌더링을 함께 검증한다.

## 이미지 오류 복구

### 원인

- 기존 Firebase Storage 파일 일부가 삭제되어 저장된 URL이 403 또는 로드 실패를 반환한다.
- 블랙우드의 활성 객실 2개는 `room_image` 행이 없다.
- 기존 `<img>`는 빈 URL과 원격 로드 실패를 처리하지 않아 깨진 이미지가 노출됐다.

### 수정

- 공통 `SafeImage`가 빈 URL과 `onError`를 로컬 플레이스홀더로 전환한다.
- 숙소 검색 카드, 숙소 갤러리, 객실 카드, 객실 상세, 리뷰 이미지, 이벤트 배너에 공통 처리를 적용했다.
- 이미지 배열이 비어 있는 객실 상세도 이미지 영역을 유지하고 플레이스홀더를 표시한다.
- 대체 이미지는 `public/images/stay-placeholder.svg` 한 파일로 관리한다.

### 검증

npm run build

```

| --- | ---: | ---: | ---: |
| 숙소 검색 목록 | 22 | 0 | 8 |
| 블랙우드 상세 | 9 | 0 | 2 |

블랙우드 상세에는 DB에서 교정된 최저가 `₩69,000`, 평점 4.8, 리뷰 12개가 표시된다.

## 핵심 사용자 흐름 안정화

### 수정

- 상세 일정 변경 모달의 정의되지 않은 `isReady` 참조를 유효한 날짜·인원 계산으로 교체했다.
- 라우트 변경 스크롤을 레이아웃 반영 전에 상단으로 이동시킨다.
- Google Maps API 키가 없는 로컬 환경에서는 지도 오류 대화상자 대신 위치 안내를 표시한다.
- 지역 입력이 비어 있어도 날짜가 있으면 전체 숙소 검색을 실행한다.
- 비밀번호 재설정 요청은 백엔드의 일반 응답을 그대로 성공 안내로 처리한다.
- 지도 검색 버튼이 선택 좌표를 부모 검색 레이아웃으로 전달한다.
- Vite의 ESM 경로 처리를 `import.meta.url` 기준으로 변경했다.
- 사용하지 않는 변수와 import를 정리하고 Framer Motion 네임스페이스를 lint가 허용하도록 명시했다.

### 브라우저 회귀 테스트

| 흐름 | 결과 |
| --- | --- |
| 검색 목록 → 블랙우드 상세 | 상단 진입 `scrollY=0` |
| 지도 API 키 없는 상세 | 오류 팝업 없음 |

| 객실 `예약하기` | 비회원 예약 선택 화면으로 이동 |
| 미등록 이메일 비밀번호 찾기 | 성공 안내, 계정 존재 여부 미노출 |

```

남은 17개는 기존 React Hook 의존성 경고이며 현재 프로덕션 빌드를 차단하지 않는다.

## 통합 데모 리허설

- 홈과 전체 숙소 검색이 정상 렌더링되고, 검색 결과는 API의 전체 건수 33개와 2페이지를 표시한다.
- 숙소 30번 상세 진입 시 화면 상단에서 시작하며 지도 API 키가 없는 로컬 환경에서도 오류 대화상자가 포커스를 가져가지 않는다.
- 블랙우드는 평점 4.8, 최저가 69,000원, 리뷰 12개와 DB 좋아요 수를 표시한다.
- 상세 이미지 9개 중 삭제된 원본 2개는 로컬 대체 이미지로 표시되며 깨진 이미지는 0개다.
- 객실 88번에서 예약 버튼을 누르면 `/reserve/guest` 선택 화면으로 이동한다.
- 존재하지 않는 이메일의 비밀번호 재설정 요청도 계정 존재 여부를 노출하지 않고 동일한 발송 안내를 표시한다.
- 최신 DB 값과 이미지 폴백이 반영된 화면 캡처를 `docs/screenshots`에 저장했다.
